# 初始发现的 Host 规则

本流程前三次成功 literature_search 的 query 各不超过4个词、96字符。优先用区分性物性/储存条件加宽领域词；三次应改变约束或同义表达。其后可用复杂查询核查比较与机制。此为查询策略检查，不是证据质量认证。

# 带独立上下文critic的研究流程 v3

本节优先于基础规范中的成稿顺序。研究者和critic都使用gpt-5.6-luna。每run最多9次critic请求（包含失败请求），用于三个阶段的审查/修改迭代，不应把次数全部耗在一个阶段。

1. 拆解题目，先发现多个可辨识候选，不预设唯一正确答案。形成候选比较简报：身份、命中的硬约束、关键支持、反证、适用范围和缺口。
2. 在成稿前补齐决定候选选择的证据。定义、综述、会议摘要、原始研究分别识别；完整PDF不自动成为原始实验。模型自行检索取证，不读取基准参考答案。
3. 调用research_critic(stage="evidence", brief=候选比较与证据角色说明, evidence_ids=实际已选证据完整ID列表)。critic revise时按issues补证/修正候选，再送审。证据还不足以选择时，不先写最终报告。
4. 证据审查通过后，选择一个有依据的条件化主方案，形成research_design。调用research_critic(stage="decision", brief=选择理由与备选比较, evidence_ids=相同已审证据集合, research_design=结构化决策)。改变证据集合或关键证据版本必须返回evidence；改变主方案须重新decision，记录为什么改变。本报告只推荐一个主方案，但同题可以有其他合格方案。
5. decision通过后，用完全一致的research_design创建报告；正文摘要、组成、机制、验证与结论贯穿同一主方案。只使用已审证据；无需把所有材料塞进正文，不复制整节引用到每段。不以未知数值掩盖核心组分未选择。
6. 调用research_critic(stage="report", brief=本次写作或修订说明, report_id=刚创建的report ID)。若只需写作修正，重建报告后再审；若退回evidence/decision，必须先完成上游审查，再重写报告。最终critic通过后report_validate；材料哈希/结构检查仍独立保留。
7. 达到critic次数或研究预算上限仍有阻塞，不伪造pass、不降标准；保留未完成状态、修改意见和原因。工具错误或拒绝不当作通过。

critic仅基于实际选定摘录和来源预览审查，不能认证未读全文、实验真实性或临床有效性。同模型不同上下文可减少历史锚定，但不是独立模型验证。critic不替研究者编造候选证据，不将意见登记为文献观察。评测仍在最终报告冻结后独立执行，不向研究者反馈参考答案或已知评分。

## 检索失败后的候选发现迭代（真实运行诊断后补充）

候选必须从可核查文献中发现，不能先猜一个常见平台后一直为它补证。先找题目最有区分度的物性、储存形式或比较关系，以它与一个宽领域词组成短查询（通常2–4个概念），再分别核查癌种、免疫指标和制剂约束。不要把全部目标塞入一个查询，也不要在发现阶段加上自己猜的载体/刺激物。分别尝试词形及同义表达；不要在每个查询都附带abstract、clinical trial或全部免疫细胞名称。

若结果连续被术语定义、专利标题、同一论文的Data/Supplementary条目占据，不把这些当作不同候选或继续堆查询词。记录这次查询不具判别力，减少非关键限定词，以稀有约束重新发现材料；对命中的原始研究取摘要/全文并立即登记证据。单独查某项约束时可暂时去掉癌种，但最终明确适用模型和外推边界。

critic连续两次指出同一主候选没有直接身份/关键属性证据，应退回候选发现，而非只把“已证实”改成“假设”后重审同一拼接方案。重新比较至少两条有文献来源的候选路径。只有出现新增决定性证据或实质改变候选论证才再次送审；保留退回原因与变更记录，不耗尽预算重复同一比较。
